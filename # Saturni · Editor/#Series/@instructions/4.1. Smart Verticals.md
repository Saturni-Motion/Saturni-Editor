### 1. SED на горизонтальной секвенции

1. `set_active_sequence <guid горизонтали>`
2. `deselect_all_clips`
3. `select_all_clips track_type=video`
4. `scene_edit_detection action=ApplyCuts sensitivity=MediumSensitivity apply_cuts_to_linked_audio=false`
   (аудио НЕ режем — оно остаётся цельным, линковка сохраняется)
5. `get_full_sequence_info` → собрать список стартов клипов V1 → это границы для анализа.
   SED иногда плодит сливеры 0.04–0.2 с у уже нарезанных склеек — это ок, разрулим на шаге 3.

### 2. Анализ кадрирования

Файл границ: JSON-массив секунд, **включая 0 и конец секвенции**, напр.
`[0, 0.44, 1.52, ..., 42.12]`. Кладём в scratchpad.

```
py -3 @tools/4.1. VReframe-SED.py \
  --render 'D:/# Video/#Поляна/Олдскул (2 сезон)/Серия N/<name> ` 1h.mp4' \
  --cuts   '<scratchpad>/cuts_<slug>.json' \
  --out    '@tools/!verticals/<name> ` 1v.json' \
  --seq 1080x1920 --scale 140
```

Скрипт: PySceneDetect классифицирует границы на «настоящая склейка» / «пауза-рез внутри плана».
Пауза-резы внутри одного плана сливаются в одну **умную сцену** с общей статичной позицией.
`static_x_norm` уже с учётом scale 140. Трек: `"V2" if (si+1)%2==0 else "V1"` (0-индексная нечётная умная сцена → V2),
кроме исключения по видеопереходам — см. 2а.

Вывод JSON: `smart_scenes[]` и `clips[]` (по одному на каждую границу из `--cuts`), у каждого клипа
`start`, `end`, `smart_scene`, `track` ("V1"/"V2"), `static_x_norm` (0..1, уже клампнут в [-0.244, 1.244]).

**Сливеры (клип ≤ ~0.2 с в своей отдельной умной сцене):** не гоним на V2. Смотрим по inPoint,
к какому соседнему плану сливер непрерывен (out одного = in другого), и присваиваем ему трек и
`x` этого соседа. Обычно сливер остаётся на V1 — тогда правок ноль.

### 2а. Видеопереходы — исключение из разбивки

Пока в материале встречались только аудиокроссфейды (они НЕ считаются) — правило ниже на
будущее, когда появятся настоящие видеопереходы.

Видеопереход (dissolve и т.п.) — это всегда **два соседних клипа на одной дорожке**. Значит если между
умной сценой **A** (до перехода) и умной сценой **B** (после перехода) стоит видеопереход:

- **B не разводится по чётности.** B кладётся на **ту же дорожку, что и A** (V1 или V2 — какая вышла у A по
  обычному счёту), чтобы переход остался валидным.
- **B метится лейблом Gray** = `set_color_label color_index=14` — **только B**, не A. A остаётся обычной
  сценой (свой трек по счётчику, обычная роль в счёте).
- **B пропускается в счёте чёт/нечёт** — счётчик на B не двигается. Сброса НЕТ. Сцена после B (C)
  получает тот слот, который достался бы B → весь счёт после B сдвигается на одну позицию.
  (То есть B «прозрачна» для счётчика, забирает только трек соседа A и лейбл.)

Пример 1 — S2 по счёту вышла на V1 (нечётный слот), переход между S2 и S3:
`S0→V1, S1→V2, S2→V1 (обычная), S3→V1 + Gray (как S2, слот не занимает), S4→V2, S5→V1, S6→V2…`
S3 занял бы V2 — этот слот уходит к S4.

Пример 2 — S2 вышла на V2 (чётный слот), переход между S2 и S3:
`S2→V2, S3→V2 + Gray, S4→V1, S5→V2…`

Цепочка переходов S1—S2—S3: и S2, и S3 — «вторые части после перехода», обе на дорожке S1, обе Gray,
ни одна не занимает слот; счёт после цепочки продолжается так, будто была только S1.
Видеопереход **внутри** одной умной сцены (между пауза-резами одного плана) на трек не влияет
(клипы и так вместе) — можно не метить.

Реализация: `4.1. VReframe-SED.py` про видеопереходы не знает (получает только список склеек). Варианты:
(а) добавить в скрипт аргумент `--video-transitions '<json [[start,end],…] сек>'`, запечь правило в `track` +
новое поле `label`; (б) вытащить переходы из `get_full_sequence_info` (`videoTracks[0].transitions`) и править
`track`/лейблы руками при разводе. Проверить, что `set_color_label` берёт **клип таймлайна** по node_id
(описание допускает и bin-элемент, и клип) — если только bin, метить вручную в Premiere.

3. `rename_project_item item_id=<nodeId> new_name="<name> ` `` ` `` `1v"`.
4. `move_item_to_bin item_id=<nodeId> target_bin=<nodeId бина v>` (бин `v` — внутри той же папки, где лежит горизонтальная секвенция: `~/Series 10/v`, `~/Series 11/v`; секвенция прямо в `~` — в `~/v`. Один `v` на папку: существующий переиспользуется, иначе создаётся. Saturni, 2026-09-24 — раньше был один общий `~/v` на прогон, и вертикалки разных серий сливались в кучу). ### 4. Развод V1/V2 (только чётные умные сцены → V2)

1. `get_full_sequence_info <guid дубликата>` → nodeId клипов V1 по индексам (идут подряд).
2. Список клипов на V2 = индексы, где `clips[i].track == "V2"` минус сливеры-исключения из шага 2
   и с учётом исключения по видеопереходам (2а): «вторая часть после перехода» B идёт на дорожку A
   (не по чётности), метится `set_color_label color_index=14`, в счёте пропускается (сдвиг, не сброс).
3. `deselect_all_clips`.
4. Для каждого nodeId из списка V2: `set_clip_selection node_id=<id> selected=true`.
5. `get_selected_clips` → проверить, что выбраны ровно нужные (по `start`).
6. `edit_timeline_uxp action=clone_selection video_track_offset=1 time_offset_seconds=0`
   → копии появляются на V2, оригиналы **остаются выделенными** на V1.
7. `lift_selection_uxp expected_sequence_guid=<guid дубликата>`
   → выделенные оригиналы снимаются с V1 без ripple. Аудио (не было выделено) цело.
8. `get_full_sequence_info` → новые nodeId: V1 (оставшиеся) и V2 (клоны, идут подряд).

`move_clip_to_track` (QE) на Premiere 26.2.2 не работает («Not Enough Parameters») — только clone+lift.

### 5. Motion на каждый клип

⚠️ **`set_clip_properties_batch` с полем `scale` СЛОМАН**: «Motion Scale is unavailable on
batch item 0». `set_clip_scale` — флаки («Could not set scale» ~30%). **Рабочий путь для Scale 140:**
после ресайза 1920×1080→1080×1920 у клипов Motion становится Scale Height 100 / Scale Width 42
(артефакт scale-to-frame). Для каждого клипа: `automate_effect_parameters_uxp action=set_value
media_type=video component_index=1 (AE.ADBE Motion) param_index=1 value=140`. Если readback вернул
`paramName: "Scale"` — готово (uniform). Если `"Scale Height"` — ещё раз с `param_index=2` value=140.
**Позицию** батчить можно: `set_clip_properties_batch` с `{node_id, position_x, position_y}` (БЕЗ scale) — работает.
Делать Scale ДО разведения V1/V2 (адресация по track 0 / clip_index проще).
Секвенция-дубликат должна быть **активной** (иначе «Clip not found for batch item 0»).
Матчим клип таймлайна ↔ запись в `clips[]` по `start` (округление 3 знака).
Сливерам даём `x` их плана-соседа (см. шаг 2).

**Loop-дубль (1-кадровый F−1 в самом конце) = тот же исходный кадр, что и самый первый клип
секвенции → у него ДОЛЖНА быть ровно та же Motion Position (тот же `static_x_norm`), что и у
первого клипа.** Это один и тот же контент, координаты обязаны совпадать — иначе на стыке петли
скачок кадрирования. Практика: берём `static_x_norm` первого клипа (умной сцены S0) и вписываем
его же loop-дублю; `scale` тот же (140), `position_y` 0.5. (Loop-дубль по правилу видеопереходов
2а и так остаётся на V1 вместе с последним клипом — см. `4.0. Looping.md` разд. B.)

## Геометрия (почему 140 и почему только X)

Источник 1920×1080, Scale 140% → контент 2688×1512 в кадре 1080×1920.
По ширине заполняет с запасом (полос слева/справа нет; диапазон X без полос = [-0.244, 1.244]).
По высоте НЕ заполняет (~200 px полос сверху/снизу; для заполнения нужно ≥178 %). Saturni принял 140.
**Эталон доли полос — 1080p на 140 (Saturni, 2026-09-24).** Видимая картинка = 1512 px высоты
в кадре 1080×1920 (полосы по 204 px). Для ЛЮБОГО исходника `4.1.` подбирает Scale так, чтобы
картинка без запечённых полос была той же высоты: `S = 1512 / activeH · 100`, где
`activeH = codedH · (1 − 2·crop%)`. 1080p → 140, 4K → 70, 1440p → 105, 720p → 210, нативный
1920×800 → 189. Запечённые полосы определяются `detect_active_picture_bounds` (образец **60 с** —
на 10–20 с были ложные «полосы» у 4K и 1080p, проверено замером) и режутся Crop Top/Bottom прямо
в `4.1.` (процент вверх до 0,5, как в `4.2.`). Position пересчитывается через масштаб `h` и
позицию `hx` клипа в горизонтали (Saturni иногда сдвигает масштаб 4K-клипов):
`p = (540 − (x_r − hx·1920)·S/h) / 1080`, clamp по видимой ширине. `4.2.` Проход 2 видит, что
масштаб уже эталонный, и ничего не трогает (фон унаследовал масштаб, Transform 140 относительный).
Вертикалка всегда **1080×1920 25 fps** (как горизонталка 1920×1080 25 fps) — `4.1.` проверяет fps
дубля и ставит 25, если нет.
Position в Premiere Motion — **нормализованная 0..1**, НЕ пиксели (док MCP врёт; пиксель → переполнение int16 → чёрный кадр). Центр = 0.5.
`static_x_norm = (1080/2 − (target_x_src − 1920/2)·1.4) / 1080`, клампнут в [-0.244, 1.244].

## Проверка кадрирования и выбор цели (2026-09-25)

**Проверка после каждого прогона 4.1 — без рендера из Premiere:**
```
node "@tools/mjs/#4.1. Dump Vertical Geometry.mjs" geom.json          # только чтение
python "@tools/#4.1. Check Verticals.py" geom.json --project-dir "<папка проекта>" --out <папка>
```
Окно кропа восстанавливается из Scale/Position клипа вертикалки и горизонтали (обратная формула
к `verticalPositionX`) поверх кадров горизонтального рендера; лица — YuNet. Вердикт на клип:
`ok` / `offc` (лицо у края) / `cut` (лицо разрезано краем) / `miss` (лица в кадре есть, в окне —
ни одного) / `two` (двойной план: одно лицо в окне, другое целиком снаружи — смотреть глазами, тот
ли говорит). На каждую вертикалку — лист-раскадровка: горизонталь с окном + 3 кадра того, что
реально видно. `cut`/`miss` — чинить всегда; `two` — сверять с текстом (кто говорит/к кому
обращаются). Экспорт кадров из Premiere (`export_frame`: QE и AME) в этой сессии не работал —
этот способ его заменяет.

**Правка готовых вертикалок без пересборки:** `@tools/4.1. Reposition Verticals.py geom.json
--project-dir … --out pos.json` (пересчёт текущей логикой `4.1. VReframe-SED.py` по склейкам
горизонтали) → `node "@tools/mjs/4.1. Apply Positions.mjs" pos.json` (по nodeId, секвенции открываются
по пути `~/<папка>/v/<имя>`). Ручная цель на отдельный клип — та же формула `pos_x()`.

**Что было не так (12 вертикалок 18.09/22.09) и что исправлено в `4.1. VReframe-SED.py`:**
1. **Ложные «лица»** — узор занавески и затылки зрителей, YuNet score 0.61–0.79, настоящие
   0.87–0.95. На общих планах сцены (Абу-шоу) ложные были крупнее комика → окно уезжало на зал
   (3 клипа `miss`). Теперь при наличии уверенного лица (≥0.82) слабые не участвуют.
2. **Двойной план, где оба помещаются** (лица + плечи ≤ 96% ширины окна) — центр на пару, а не на
   одного (Звёзды в Ауте: говорящую ведущую справа резало краем).
3. **Лицо, разрезанное краем окна** — окно сдвигается, чтобы соседнее лицо ушло целиком (или вошло
   целиком, если так ближе), не выпуская главное. Та же проверка применяется к итоговой медиане
   умной сцены (медиана по кадрам сама умела разрезать лицо).
4. **Склейка, которую PySceneDetect пропустил** — `min_scene_len` был 15 кадров (склейка в 0.56 с
   от начала терялась, короткий двойной план сливался с планом ведущей). Теперь `min_scene_len=3`
   + второй признак: разница кадров до/после границы SED (пауза-рез ≤16, смена плана ≥39, порог 28).
5. **Кто говорит в двойном плане, который не влезает целиком** — оптический поток по рту ошибается
   (Моргунова №3 22.09: отвечает Прохор, окно на Лёле) — автоматически не решено; проверка даёт
   `two`, сверять с текстом, править вручную через `pos_x()` → `4.1. Apply Positions.mjs`.

**Выбор цели с 2026-10-07 (стенд на 17 роликах «Околоточного», разбор —
`#analysis/Verticals-07.10 (Околоточный)/#Verticals-07.10.md`).** Цель прежнего алгоритма (поток в
нижней половине лица — лучше всего угадывал говорящего) остаётся главной. Поверх неё
`refine_target()` в `4.1. VReframe-SED.py` использует головы по позе YOLO11-pose (профиль, спина,
мелкий общий план) и лицам на полном кадре:
- затылок на переднем плане заменяется на лицо, повёрнутое к камере;
- соседние головы не режутся краем окна;
- пара берётся только если влезает в 85% окна;
- тот же ракурс, что уже был в ролике, получает ту же позицию (`shot_consistency()`).

Модель `@tools/models/yolo11s-pose.pt`, пакет `ultralytics`; без них или с `--legacy` — прежний алгоритм.
В JSON у сцены есть `target_x_legacy` (что выбрал бы старый) и `same_shot_as`.

**2026-10-29 (Мусор, 1920×800 в рендере 1080, тёмная гамма):** смена плана давала
разницу кадров 15–20 (< 28) — серия сливалась в одну умную сцену с одной позицией. Теперь
`classify_boundaries` считает только по строкам картинки (без чёрных полос) + корреляция кадров
≤ 0.15 = смена плана. Бин `s1` = папка `Серия 1` при поиске рендера (4.1 и проверка). Проверка
строгая на шлемы/затылки — `miss`/`cut` смотреть глазами, чинить только реально пустое окно.

## Ограничения

- **Кейфрейм-пан невозможен через MCP.** `automate_effect_parameters_uxp` — значение скалярно-защищено;
  `set_effect_property "Position"` → EvalScript error; CEP `add_keyframe` — только скаляр.
  Скалярные кейфреймы (Scale/Rotation/Crop) работают, 2D Position — нет. Поэтому статикой на клип.
- `manage_timeline_selection_uxp` replace/add не строит произвольный selection — только `set_clip_selection` по nodeId.
- MCP `undo` сломан (`app.project.undo is not a function`) — откат только вручную Ctrl+Z.
- `export_frame` для проверки надёжнее `capture_frame`.
- Секвенцию `c` в каждом бине — всегда пропускаем.
